# 2023math

암호화 알고리즘의 성능 분석 — 암호화 방식에 따른 속도 차이를 중심으로

> [!NOTE]
> RSA와 ECC를 직접 구현해 단계별 소요 시간을 측정·비교한 수학 탐구 프로젝트

## 연구 동기

- 소인수분해 기반 **RSA**: 대표적 공개키 암호
- 타원곡선 기반 **ECC**: 상대적으로 새로운 방식
- 두 알고리즘의 차이점·장단점 분석

## 연구 문제

1. 알고리즘에 따른 속도 차이 존재 여부
2. 속도에 영향을 주는 요소

## 실험 방법

1. 암호화 과정을 3단계로 세분화
   - 키 생성용 소수 준비
   - 공개키·비밀키 생성
   - 암호화
2. 단계별 시간 측정 코드 삽입
3. 10만 회 반복 후 평균값 산출
   - 5만 → 10만 회 증가 시 결과 변동 거의 없음 → 10만 회로 결정
4. 결과 기반 성능 영향 요소 분석

## 실험 결과

단위: 초 (평균)

| 단계 | RSA | ECC |
| --- | --- | --- |
| 소수 준비 | 0.000196 | 0.000000 |
| 키 생성 | 0.220435 | 0.001980 |
| 암호화 | 0.000012 | 0.000010 |
| **합계** | **0.220644** | **0.001990** |

> [!TIP]
> 결론
> - 두 알고리즘 모두 **공개·비밀키 생성**이 전체 시간의 대부분 차지
> - ECC가 약 100배 이상 빠름 → 키 크기 차이가 원인
> - RSA: 큰 소수 두 개의 소인수분해 이용 / ECC: 미리 정의된 타원곡선 이용 → 더 작은 키로 동일 수준 보안 제공
> - 성능 개선 핵심 = 키 생성 시간 단축

## 구현 내용

### RSA

- 소수 p, q: 750 ~ 1000 범위에서 무작위 선택
- n = p × q, φ(n) = (p − 1)(q − 1)
- 공개키 e: φ(n)과 서로소인 최소 정수
- 비밀키 d: (e × d) mod φ(n) = 1
- 평문: 8자리 랜덤 영문 문자열 → 문자별 C = Mᵉ mod n

### ECC

- 곡선: y² = x³ + 4x + 20 over F₂₉
- 기준점 G = (1, 5), 위수 37
- 점 덧셈, 두 배, 스칼라 곱 (left-to-right binary)
- 모듈러 역원: 확장 유클리드, 거듭제곱: square-and-multiply
